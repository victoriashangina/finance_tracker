# Как открыть приложение в интернете

Эти шаги выполняются после загрузки исходного кода на GitHub. Для Django нужен сервер Python и постоянная база PostgreSQL. GitHub Pages предназначен для статических страниц и этот проект не запускает.

## Вариант: Render

1. Войди в свой аккаунт Render и создай PostgreSQL. При выборе тарифа проверь стоимость, ограничения и срок хранения базы. В этой поставке никакие платные ресурсы не создавались.
2. Сохрани **Internal Database URL** этой базы. Не добавляй его в репозиторий. База и веб-сервис должны быть в одном регионе.
3. Создай **Web Service**, подключи свой репозиторий GitHub и ветку `main`.
4. Выбери среду **Python**. Если `manage.py` в корне репозитория, поле Root Directory оставь пустым. Если загрузила папку целиком, укажи её путь.
5. Build Command: `sh build.sh`. Скрипт устанавливает закреплённые зависимости, собирает статические файлы и применяет миграции.
6. Start Command: `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 90 --access-logfile -`.
7. Health Check Path: `/health/`.
8. В Environment добавь переменные из таблицы ниже и запусти Deploy.

| Переменная | Значение |
| --- | --- |
| `DEBUG` | `False` |
| `SECRET_KEY` | Собственная длинная случайная строка |
| `DATABASE_URL` | Internal Database URL твоей PostgreSQL |
| `EMAIL_HOST` | SMTP-сервер для восстановления паролей, если используешь почту |
| `EMAIL_PORT` | Обычно `587`; значение должен подтвердить почтовый провайдер |
| `EMAIL_USE_TLS` | `True` для SMTP STARTTLS |
| `EMAIL_HOST_USER` | SMTP-логин |
| `EMAIL_HOST_PASSWORD` | SMTP-пароль приложения или провайдера |
| `DEFAULT_FROM_EMAIL` | Разрешённый провайдером адрес отправителя |

Сгенерировать секрет в активированном Python-окружении:

```sh
python -c 'from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())'
```

Результат вставляется только в настройки хостинга. Не публикуй его в README, коммитах или переписке. Не меняй рабочий SECRET_KEY при каждом перезапуске: это нарушит существующие сессии и токены восстановления.

`.python-version` задаёт Python 3.12. Render передаёт `RENDER_EXTERNAL_HOSTNAME`; приложение автоматически добавляет этот домен в разрешённые хосты и доверенные CSRF origins. Для собственного домена дополнительно задай:

```text
ALLOWED_HOSTS=your-domain.example
CSRF_TRUSTED_ORIGINS=https://your-domain.example
```

После успешной сборки открой адрес сервиса, создай аккаунт, нажми «Показать демо», проверь импорт и выход/вход. Статика раздаётся WhiteNoise, HTTPS завершается на прокси хостинга. В production включены перенаправление на HTTPS и защищённые cookies. Не используй `runserver` как публичный сервер.

Без SMTP можно показать остальные функции, но письмо восстановления доставлено не будет. Для проверки почты запроси восстановление на собственный адрес и убедись, что письмо пришло. Локальный вывод письма в терминал не подтверждает работу внешней доставки.

## Обновления

При включённом автодеплое новый push в `main` запускает обновление. Миграции входят в репозиторий и применяются `build.sh`. Эта конфигурация подходит для одной учебной копии; изменения схемы для работающей системы с несколькими версиями сервера требуют отдельного планирования миграций и резервного копирования.

Пользовательские записи хранятся в PostgreSQL, а не на временном диске веб-сервиса. Сохраняй и проверяй резервные копии через возможности выбранного сервиса БД.

## Частые причины ошибки

- **DisallowedHost / 400:** домен отсутствует в `ALLOWED_HOSTS` или хостинг не передаёт `RENDER_EXTERNAL_HOSTNAME`.
- **CSRF / 403:** неверная схема/домен в `CSRF_TRUSTED_ORIGINS`, неправильная настройка HTTPS-прокси или устаревшая форма. Обнови страницу после входа.
- **Не подключается база:** проверь DATABASE_URL, регион, доступность базы и правильность пароля.
- **Нет таблиц:** не завершился `python manage.py migrate`.
- **Нет оформления:** не завершился `collectstatic` или неверен STATIC_ROOT.
- **Письмо не приходит:** проверь SMTP, разрешённый отправитель, спам и ограничения исходящей почты хостинга.
- **После перезапуска исчезли данные:** использовалась SQLite на временном диске. В production нужен DATABASE_URL к PostgreSQL.

## Границы учебной версии

Внешнее размещение ещё не выполнено: для него нужны твой репозиторий и твой хостинг. Проект подготовлен для такого запуска, но внешняя сборка, домен, тариф и доставка почты не проверялись.

Для демонстрации используй вымышленные данные. Переход к общедоступному финансовому продукту потребует дополнительной проверки безопасности, лимитов запросов и загрузок на прокси, защиты административного входа, резервирования и мониторинга. Приложение не получает банковские пароли, не проводит платежи и не обещает поддержку выписок всех банков.

Официальные инструкции: [Render: Deploy a Django App](https://render.com/docs/deploy-django), [Django deployment checklist](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/).
